# AppSwitch

**按住 Option，按下 Tab，在你选择的应用窗口之间快速切换。**

AppSwitch 是一个开源的 macOS 菜单栏工具。无论你开着多个 VS Code 项目，还是同时使用浏览器和终端，都可以把需要的应用加入同一个窗口列表，直接找到并跳转到目标窗口。

原生 Swift + SwiftUI + AppKit 开发，无第三方依赖，无网络请求，采用 [MIT 许可证](LICENSE)。

## 界面预览

### 窗口切换列表

![AppSwitch 窗口切换列表：显示应用图标、窗口标题、选中状态和最小化标记](docs/images/window-switcher.png)

同一个列表中显示不同应用的窗口。高亮行表示当前选择；VS Code 窗口突出项目名，同时保留原始标题；最小化窗口带有标记。截图使用内置演示数据，不包含真实工作内容。

设置页提供“参与切换的应用”“首次使用”和“当前运行的应用”等区域：可以添加或停用应用、查看辅助功能与系统热键状态，并调整快捷键和 VS Code 标题识别方式。辅助功能授权由你在 macOS 系统设置中手动完成。

## 可以做什么

- **选择参与切换的应用**：默认包含 VS Code，也可添加其他 `.app`；支持临时停用和移除。
- **按窗口切换**：直接选择某个项目或窗口，显示对应应用的真实图标。
- **固定列表顺序**：同一次运行期间，已有窗口保持相对位置，新窗口追加到末尾；最近使用记录只影响初始选中项。
- **键盘与鼠标操作**：支持反向选择、方向键、松开 Option 确认、Esc 取消和点击跳转。
- **恢复最小化窗口**：选择后恢复并激活目标窗口。
- **发现其他桌面的窗口**：通过 macOS 辅助功能和应用原生窗口菜单补充窗口信息；具体效果取决于目标应用。
- **本地运行**：不读取项目文件内容，不发送窗口标题，无需账号。

## 系统要求

| 项目 | 要求 |
| --- | --- |
| 操作系统 | macOS 13 Ventura 或更新版本 |
| 安装镜像 | 打包脚本生成 Apple 芯片（arm64）版本，Intel Mac 请从源码构建验证 |
| 源码构建 | Xcode 或 Command Line Tools，包含 Swift 5.9+ |
| 窗口读取与切换 | 需要辅助功能权限 |
| 输入监控 / 屏幕录制 | 不需要 |

## 快速开始

### 方式一：从源码构建

当前仓库可直接从源码构建。打开“终端”，依次执行：

```sh
git clone https://github.com/binbinku/AppSwitch.git
cd AppSwitch
zsh scripts/build-app.sh
zsh scripts/install-app.sh
open /Applications/AppSwitch.app --args --settings
```

构建生成 `dist/AppSwitch.app`，安装脚本将它复制到 `/Applications/AppSwitch.app`。如果没有编译工具，可先运行 `xcode-select --install` 并按系统提示完成安装。

建议安装到“应用程序”后再授权，并始终使用这一份。构建和安装脚本会拒绝覆盖正在运行的 AppSwitch；升级前请先从菜单栏退出 AppSwitch。

### 方式二：安装 DMG

如果 [Releases](https://github.com/binbinku/AppSwitch/releases) 中提供了安装镜像，可以直接下载，无需安装开发工具。没有可下载的版本时，请使用上面的源码构建方式。

1. 下载适合你设备的 `.dmg` 文件。
2. 打开镜像，将 **AppSwitch** 拖到 **Applications（应用程序）**。
3. 推出镜像，再从“应用程序”启动 AppSwitch。
4. 按下面的步骤完成辅助功能授权。

当前打包脚本生成的镜像仅适用于 Apple 芯片 Mac，使用本地临时签名，未经过 Apple 公证。首次打开如被系统阻止，请确认来源可信后，在“系统设置 → 隐私与安全性”中按系统提示允许打开。

### 首次使用：授权并选择应用

1. AppSwitch 启动后常驻**屏幕顶部菜单栏**，不显示 Dock 图标。点击菜单栏的叠放窗口图标，打开“设置与权限…”。
2. 点击“授权辅助功能”，前往“系统设置 → 隐私与安全性 → 辅助功能”。
3. 添加并启用 `/Applications/AppSwitch.app`，必要时退出 AppSwitch 再重新打开。以 AppSwitch 设置中显示“**辅助功能：已授权**”为准。
4. 在“参与切换的应用”中保留 VS Code，或点击“添加应用…”选择其他应用；确保对应开关已启用。
5. 打开这些应用及其窗口，按住 **Option（⌥）**，按 **Tab** 显示列表，继续按 Tab 选择，松开 Option 跳转。

添加应用不会自动启动它。只会列出已启用、正在运行且能提供窗口信息的应用；移除应用也不会关闭它的窗口。

## 快捷键

以下为默认快捷键，Option 键也标为 `⌥` 或 `Alt`。

| 操作 | 效果 |
| --- | --- |
| 按住 `⌥`，按 `Tab` | 打开列表并选择下一个窗口 |
| 保持按住 `⌥`，继续按 `Tab` | 向后循环选择 |
| `⌥ Shift Tab` | 反向选择 |
| 松开 `⌥` / 按 `Return` | 确认并切换 |
| 方向键 | 在列表中移动选择 |
| `Esc` / 点击列表外 / 点击关闭按钮 | 取消切换 |
| 点击某一行 | 立即跳转到该窗口 |

也可以从菜单栏点击“显示窗口列表”，让列表保持打开，再点击目标窗口或按 Return 确认。

在设置中可以将唤起快捷键改为 `⌃ ⌥ Tab` 或 `⌥ Space`。无论选择哪一种，松开 Option 都会确认，加入 Shift 则反向选择。

### 列表为什么不会随使用频率重排？

固定位置便于记住目标窗口在哪里。已有窗口在本次运行中保持相对顺序；新增窗口排到末尾，关闭的窗口移出列表。最近使用记录用于初始选中，方便切回上一个窗口，但不会改变每行的位置。AppSwitch 重启后会重新建立顺序。

### 让 VS Code 项目名更清楚

AppSwitch 会尝试从 VS Code 标题中识别项目名。若你使用了自定义标题，可以在 AppSwitch 设置中选择“项目名在前”“文件名在前”或“完整原始标题”。

推荐在 VS Code 的**用户级** `settings.json` 中合并以下设置，再将 AppSwitch 的识别方式改为“项目名在前”：

```json
{
  "window.title": "${rootName}${separator}${activeEditorShort}"
}
```

自动识别是启发式判断，完整原始标题始终保留。同名项目可以通过 `${rootPath}` 或不同的 `.code-workspace` 名称区分。标题识别仅作用于 VS Code 系列，其他应用保留完整窗口标题。AppSwitch 不会自动修改 VS Code 设置，也不需要安装扩展。

## 常见问题

### 启动后找不到窗口或 Dock 图标

这是菜单栏应用，正常运行时没有 Dock 图标。请点击屏幕顶部的叠放窗口图标，选择“设置与权限…”。也可以运行：

```sh
open /Applications/AppSwitch.app --args --settings
```

### 系统权限开关已打开，AppSwitch 仍显示未授权

本地临时签名可能在重新编译或升级后变化，系统保留的旧授权不一定适用于新二进制。

1. 从菜单栏退出 AppSwitch，确认新版已安装到固定位置。
2. 在“辅助功能”列表中移除旧 AppSwitch 条目。
3. 重新添加 `/Applications/AppSwitch.app`，开启权限，再从该路径启动。
4. 在 AppSwitch 设置页核对“当前运行的应用”路径和授权状态。

不要同时运行 `dist` 和“应用程序”中的两份 AppSwitch。

### 按快捷键没有反应

先从菜单栏点击“显示窗口列表”。若列表可以打开，请在设置中查看“系统热键”是否已注册，尝试其他组合后点击“重新检查”。热键可能被其他软件占用；设置页会显示系统错误码和最近触发时间。唤起热键本身不依赖辅助功能权限，但读取和切换窗口需要该权限。

### 列表为空，或某个应用的窗口没有显示

检查该应用是否已添加、启用、正在运行并打开了窗口，以及 AppSwitch 是否已获辅助功能授权。目标应用需要通过 macOS 辅助功能或原生“窗口”菜单提供可识别的窗口信息，因此不同应用的兼容性可能不同。

### 能否切换到其他桌面或全屏窗口？

AppSwitch 会结合辅助功能窗口和原生“窗口”菜单发现目标，并通过目标应用提供的接口跳转。不使用私有 Space API。不同应用、全屏和多显示器环境的效果需要实际验证。

如果无法自动跳转桌面，可检查“系统设置 → 桌面与程序坞 → 调度中心”中的“切换到某个应用程序时，切换到包含该应用程序的打开窗口的空间”。

### 会不会影响原来的 CodeSwitch？

AppSwitch 使用独立名称和 Bundle ID：`dev.appswitch.app`，安装目标为 `/Applications/AppSwitch.app`，不会替换 CodeSwitch 或自动迁移其偏好设置。首次使用需单独授权并配置应用列表。如果同时运行两者，应选择不同快捷键以避免占用；也可先使用 AppSwitch 演示模式查看界面。

### 是否支持开机启动？如何卸载？

目前没有内置开机启动开关，需要时可在 macOS“系统设置 → 通用 → 登录项”手动添加 AppSwitch。卸载时先从菜单栏退出，再将 AppSwitch.app 移到废纸篓；可同时在辅助功能和登录项中移除对应条目。

## 隐私与权限

- 辅助功能用于读取窗口标题、识别窗口和激活所选窗口，由用户手动授权。
- 应用本身无网络请求，不上传窗口标题，不读取项目文件内容。
- 应用列表、快捷键和标题识别方式保存在本机偏好设置中。
- 不需要输入监控或屏幕录制权限。
- 诊断文件仅在显式传入参数时写入，包含状态、计数及运行路径，不包含窗口标题或文件内容。

## 开发与验证

```sh
swift test
zsh scripts/build-app.sh
```

核心逻辑测试覆盖固定窗口顺序、最近窗口选择、菜单重建、应用列表持久化、标题识别、双向循环，以及加载期间的快速按键和取消行为。系统授权、跨桌面、全屏和多显示器行为仍需实机验证。

不授权也可以预览界面：

```sh
open -n dist/AppSwitch.app --args --demo
```

独立演示模式使用示例数据，不注册系统热键，不切换真实窗口。正常模式下，设置页也提供“界面预览”入口。

如需排查问题，可显式指定诊断文件路径：

```sh
open dist/AppSwitch.app --args --diagnostic-file /tmp/appswitch-status.json
```

### 打包与签名

```sh
zsh scripts/package-release.sh
```

当前版本生成 `dist/AppSwitch-1.4.0-macOS-arm64.dmg` 和对应的 `.sha256` 校验文件，镜像包含应用、Applications 快捷入口和中文安装说明。打包在独立目录中完成；已有同名发布文件时脚本会停止，避免覆盖。

本机构建默认使用临时签名。如有 Apple Developer 签名身份，可以指定：

```sh
APPSWITCH_SIGN_IDENTITY='Developer ID Application: Your Name (TEAMID)' zsh scripts/build-app.sh
```

公开分发时应完成 Developer ID 签名与 Apple 公证；当前脚本没有自动公证流程。
